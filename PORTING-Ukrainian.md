# PORTING.md — Посібник з перенесення open-english (скорочена версія)

> **З (2026-08-27)**: нові патерни — кроссдоменне iframe-сховище для секретів, універсальні хелпери шифрування (`owEncryptSecret`/`owDecryptSecret`) — див. PORTING.md (японською) для записів від 2026-08-27.


> **Примітка**: це скорочений переклад. Повний технічний посібник з
> деталями коду та підводними каменями залишається доступним лише
> японською в [PORTING.md](PORTING.md) — звіряйтеся з ним перед
> фактичним застосуванням будь-якого патерну.

Короткий огляд придатних для повторного використання патернів
реалізації з цього проєкту, на випадок перенесення в інший проєкт:

1. **Патерн інтеграції з `aruaru-llm`**: вимагає підтримки CORS
   (`.with_cors()`) та штрафу за повторення
   (`generate_with_repetition_penalty`, за замовчуванням 1,3) на боці
   `aruaru-llm`, інакше браузер блокує `fetch()`, або жадібне
   декодування GPT-2 потрапляє в цикл повторень.
2. **Витягування мови для TTS** (`extractSpeechText`): розділяє
   двомовні рядки у форматі "English / 日本語" перед передачею до
   `SpeechSynthesisUtterance`, щоб уникнути переривчастої вимови.
3. **Набір іконок запуску** (`icons/` + `manifest.json` +
   `launchers/`): написаний вручну PNG/ICO-кодер без зовнішніх
   графічних інструментів, плюс скрипти для `.lnk` Windows, `.desktop`
   Linux та `.app` macOS.
4. **Автооновлення** (`auto-update.js` + `version.json`): простий
   опитувальний цикл `buildId` кожні 5с з `location.reload()`.
5. **Статичний сервер на основі RPoem** (`server/`): замінює `python3
   -m http.server` крейтом Rust, що повторно використовує
   `static_file_handler` з `open-runo-poem-compat`.
6. **Структурна гарантія гібридних відповідей** (`ensureHybridReply`):
   автоматично додає коротку примітку японською, якщо відповідь моделі
   не містить японської — без перебільшення якості перекладу.
7. **Керування версіями + очищення старих версій на боці браузера**:
   `version.json` з полем `version`, видалення власних ключів
   `localStorage` застосунку при новій версії.
8. **Міст до Google Custom Search JSON API + панель налаштувань у
   браузері**: облікові дані лише в пам'яті процесу, ніколи на диску.
9. **Інсталятор для Windows (Inno Setup) — реальні кроки перевірки**:
   `PrivilegesRequired=lowest` проти зависань UAC,
   `MSYS_NO_PATHCONV=1` для тихого встановлення з Git Bash.
10. **Гео-/туристична БД з попередженнями про безпеку, що залежать від
    теми**: пошук за підрядком замість точного збігу; для небезпечних
    тем (наприклад, альпінізм) завжди додавати попередження про
    безпеку.
11. **Автооновлення через GitHub Releases (лише Windows)**: має бути
    реалізовано на нативному боці (не в JS браузера); власний
    запущений .exe не можна видалити у Windows — спочатку запустити
    відокремлений batch-скрипт, потім завершити власний процес.
12. **CSS-класам модальних вікон потрібні `max-height`/`overflow-y`**:
    кожен клас контейнера модального вікна має визначати можливість
    прокручування, інакше довгий контент недоступний на мобільних
    пристроях.
13. **Включення Rust-сервера в Android**: робити шляхи перевизначуваними
    під час виконання через змінну середовища; завжди захищати
    специфічну для Windows логіку автооновлення через
    `cfg!(target_os = "windows")`.

14. **Кросплатформне автооновлення з відкатом (rollback) на основі
    перевірки працездатності**: узагальнити `apply_update_linux` у
    `apply_update_unix` (Linux і macOS використовують однакову заміну
    працюючого бінарного файлу); зберігати поточний бінарний файл перед
    застосуванням оновлення; після запуску нової версії перевіряти
    новий ендпойнт `/healthz` за короткий час, у разі невдачі —
    відновлювати резервну копію. Android/iOS явно залишаються поза
    межами (обмеження платформи, а не недогляд).
15. **Просування + автоматичне встановлення RSync**: якщо `rsync` не
    знайдено, показувати дружнє двомовне повідомлення ("Let's install
    RSync!") замість сухої помилки, потім намагатися автоматично
    встановити його через ланцюжок менеджерів пакунків залежно від ОС
    (winget→choco у Windows, apt-get→dnf→pacman у Linux, brew у macOS,
    pkg у Termux/Android), і одразу запускати резервне копіювання в разі
    успіху.
16. **Окрема вхідна сторінка для обмеженого каналу доступу** (наприклад,
    `facebook.html` для користувачів із доступом лише до Facebook):
    проста статична сторінка, що повторно використовує наявні у README
    посилання для завантаження, з явним чесним розкриттям того, що
    офіційний безкоштовний "zero-rated" доступ не досягається — це лише
    альтернативна точка входу.

## Шаблон: оригінальні багатомовні тести + вибір мов + озвучення (2026-08-22)

1. Розділити дані на два файли: завдання тесту та фрази для озвучення
   мають різні призначення.
2. Надати зведений API без текстів завдань (`GET /v1/world-languages`), а
   повний JSON завантажувати лише під час фактичного запуску тесту.
3. Не переписувати наявний інтерфейс тестів: достатньо додати
   `<optgroup>` зі значеннями `world:<code>` і повторно використати
   перевірку та перехід до викладача.
4. Обмеження на кількість мов задавати на рівні прапорців; після
   досягнення межі вимикати **лише невідмічені** прапорці.
5. Використати наявний TTS, додавши тільки таблицю відповідності коду
   мови та тегу BCP-47; чесно зазначати, що без встановленого голосу
   текст лише відображається.
6. Показувати тексти в `readonly`-`<textarea>` (можна копіювати), а для
   збереження використовувати наявний ендпойнт, без нових таблиць.

## Шаблон: правилові відповіді фіксованим текстом на чутливі теми (2026-08-23)

1. Три частини: функція визначення за ключовими словами + таблиця текстів
   із ключем за кодом мови + функція, що збирає двомовну відповідь.
   Ставити в обробник надсилання **перед** шляхом до ШІ.
2. Поєднувати слово-тему І слово-намір, щоб побіжно згаданий «Іран» не
   перехоплював звичайну розмову. В англійських ключах ставити межу слова
   `\b` **лише на початку**, інакше губиться «Zoroastrianism» (реально
   трапилася помилка).
3. Конкретніші теми перевіряти раніше (666 перед історією релігій).
4. Гарантії чесності писати просто в текст: гіпотези **представляти**,
   міські легенди **називати легендами** (за можливості з технічним
   розбором, як із захисними рисками штрихкоду), збіги **називати
   збігами**; «цікаві паралелі» між давнім текстом і сучасністю
   **подавати лише як можливість** («так кажуть деякі») і ніколи як
   справджене пророцтво (приклад: Одкровення 13:16-17 «без начертання не
   можна ні купувати, ні продавати» поряд зі штрихкодами й онлайн-платежами
   на кшталт Amazon).
5. Потрібні застереження **не мусять** бути сухими формальними
   дисклеймерами: тепле, легке формулювання цілком годиться, якщо читач
   ясно розуміє, що нічого не доводиться (напр. «сприймайте це радше як
   кумедну дрібничку, ніж як переконливий доказ»). Перевірка — **«чи
   стверджується щось як факт?»**, а не тон. Але пом'якшення ніколи не
   повинно сповзати у формулювання, які читаються як твердження
   («пророцтво справдилося», «це справді відбувається»).
6. Фіксувати вилучені твердження та причину — і в тексті відповіді, і в
   коментарі коду («прочитати перед зміною»).

## Шаблон: фіксований текст + двоетапна розмова на одному прапорці (2026-08-23)

Вікторина з оригінальною задачею автора (`9 ◯ 9 ◯ 9 ◯ 9 = 10`, відповідь
`(9 × 9 + 9) ÷ 9 = 10`) переноситься як розширення попереднього шаблону
правилових фіксованих відповідей.

1. Та сама трійця: розпізнавання за ключовими словами (`isQuizRequest()`),
   таблиця текстів із ключем за кодом мови (`QUIZ_TEXTS`) і збирачі
   відповіді (`quizQuestionText()` / `quizAnswerText()`). Ставити в
   обробник надсилання **перед** шляхом до ШІ; денний ліміт не витрачати.
2. **Двоетапну розмову тримати на одному булевому прапорці** —
   `quizAwaitingAnswer`. Умова ставить його в `true`; окремий розпізнавач
   (`isQuizAnswerRequest()` — «не знаю», «скажи відповідь») спрацьовує
   **лише поки прапорець піднято**, після видачі розв'язку скидає його.
   Ні кінцевого автомата, ні збереження стану на сервері не потрібно.
3. **Обчислення не доручати мовній моделі.** Правильність арифметики має
   бути перевірною ззовні (калькулятор, рахівниця), тому відповідь —
   написаний вручну незмінний текст.
4. **Вибір мови — окремою маленькою функцією** (`quizPreferredLangCode()`):
   узяти мову вивчення або рідну мову, і якщо переклад є — додати його
   спереду до типової японсько-англійської пари.
5. **Чесно позначати межу перекладів.** Тексти є лише для
   ja/en/es/fr/de/zh/ko; решту зі 130 мов **не заповнювати** машинним
   перекладом заради вигляду «всі мови підтримано» — краще типова пара
   й пряме зізнання про обмеження.
